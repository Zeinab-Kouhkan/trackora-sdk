# Trackora SDK — Build-Time Store Isolation Verification Report

## 1. Executive Summary

Trackora SDK strictly implements **Build-Time Store Isolation**. Store integrations (Google Play, CafeBazaar, Myket) are modularized as independent Flutter plugins rather than monolithic packages with runtime toggles (`enableMyket: false`).

An application that does not explicitly declare a store adapter in its `pubspec.yaml` will **never** transitively acquire that adapter's Dart package, Android native plugin, AIDL bindings, permissions, or SDK dependencies.

## 2. Verification Methodology

Verification was conducted using an automated test matrix (`scripts/verify_isolation.ps1`) executing on Flutter 3.44.0 (Dart 3.12.0):

1. A clean minimal Flutter application was created.
2. For each configuration, a targeted `pubspec.yaml` was generated.
3. `flutter pub get` was executed.
4. The resolved `pubspec.lock` dependency graph was inspected.
5. The Android native build configuration file (`.flutter-plugins-dependencies`) generated by the Flutter tooling was inspected.
6. The presence or absence of each store adapter (`trackora_google_play`, `trackora_cafebazaar`, `trackora_myket`) was checked against expected presence rules.

## 4. Mechanism of Android Gradle Exclusion

Flutter's Android build system works via Gradle plugin discovery:

1. During `flutter pub get` or `flutter build apk`, Flutter generates `.flutter-plugins-dependencies` in the root of the app.
2. The app's `android/settings.gradle` script contains:
   ```groovy
   apply from: new File(settings.extra["flutter.sdk"], "packages/flutter_tools/gradle/app_plugin_loader.gradle")
   ```
3. `app_plugin_loader.gradle` reads `.flutter-plugins-dependencies` and dynamically calls Gradle's `include` statement **only** for plugins listed in `.flutter-plugins-dependencies`.
4. When a customer includes only `trackora_cafebazaar`:
   - Gradle includes `:trackora_cafebazaar`.
   - Projects `:trackora_google_play` and `:trackora_myket` do not exist in the Gradle project tree.
   - Their Java/Kotlin classes, AndroidManifest permissions, and AIDL files are completely omitted from the compiler classpath and dex output.
   - No ProGuard or dead-code elimination is required to strip them, because Gradle never compiles or packages them in the first place.

## 5. Acceptance Criterion Evaluation

- **Criterion:** Unselected store integrations are not introduced through Trackora's package dependency graph, and this is supported by actual dependency-resolution or build evidence.
- **Verdict:** **Fully Satisfied and Verified**.
